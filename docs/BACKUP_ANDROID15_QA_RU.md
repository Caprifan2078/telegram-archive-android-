# QA: резервное копирование на Android 15

## BACKUP-15 (P0): ложный отказ восстановления

Коммит 73d3aed: [общий Android 15 прогон](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40482486471) обнаружил два отказа тестов восстановления: резервная копия отклонена как повреждённая. Лог SQLite показывает попытку команды FTS integrity-check записать в базу, открытую только для чтения. Это указывает на возможную причину; необходимо проверить исправление на эмуляторе.

Экспериментальная правка: quick_check выполняется на отдельной временной копии проверенной базы с правом записи; исходный проверенный файл остаётся неизменным и используется при восстановлении. Добавлены тесты FTS, целостности исходных байтов, удаления временных файлов и отказа повреждённой базы; существующие тесты полного восстановления и переноса заметок запускаются на API 30, 34 и 35. Проверка потребует дополнительное свободное место размером до одной базы. Состояние: **не проверено, нельзя считать исправленным до завершения прогонов**.


На первом исправленном срезе оба исходных Android 15 теста восстановления прошли; полный прогон всё ещё не прошёл из-за нового теста, который ожидал ровно один файл рядом с базой, хотя SQLite может оставлять собственный журнал. Уточнена проверка: она проверяет отсутствие любых файлов временной проверочной копии по её префиксу. Не утверждать исправление до повторного запуска. Android 11: [первый прогон](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40483618052), Android 14: [первый прогон](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40483617838), Android 15: [полный прогон](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40483617798).


Итог ветки 2a0ebeb: Android 11 46/46 и Android 14 59/59 прошли; повтор полного Android 15 — 117 успешно, один двухфазный тест подписи пропущен. В первом Android 15 прогоне этого среза были три ошибки фокуса/активного окна, при повторе они не возникли; причина не установлена. Сохранность исходных байтов и отказ повреждённой базы проверены. После интеграции нужны новые прогоны.
