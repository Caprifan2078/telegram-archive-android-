# Базовый пользовательский сценарий — разбор баг-репорта 0.50

**Дата разбора:** 26.10.2026. **Ветка:** `qa/v052-duplicate-id-safety-20261026`.
Цель — сначала подтверждать наличие дефекта в текущей версии, потом вносить
минимальное исправление с тестами. Не считать совпадение с прежним
скриншотом доказательством существования бага в текущем приложении.

## Критерий стабильности для обычного пользователя

Можно импортировать HTML-экспорт без потери прежнего архива; читать,
искать, возвращаться к сообщению; открывать/ставить на паузу/перематывать
доступные кружки, голосовые, фото и GIF; при отсутствии оригинала
приложение ясно сообщает о проблеме без ложной индикации воспроизведения
или падения. Временный скачок FPS — не основание объявлять потерю данных.

## Подтверждённые проблемы обычного чтения (26.10.2026)

- **P1 — медиафайлы с символами #/? в именах.** Был конкретный дефект
  `DocumentFolder.resolve`: сначала `Uri.decode`, потом удаление
  `?/#` приводило к обрезанию настоящего имени файла с `%23/%3F`.
  Исправлен порядок: отделять *неэкранированные* суффиксы до
  декодирования. Добавлен Android-тест
  `ExportMediaFilenameRegressionTest` с реальными синтетическими
  именами на диске (`#`, `?`, `%23`), URL-суффиксами и отказом
  при попытке выхода из каталога. Реальные пользовательские файлы
  не используются.
- **P1 — произвольный выбор закрепа при любом `jump`.** Был
  конкретный дефект: переход из поиска или по reply-to пересчитывал
  `pinnedFocus` по ID, даже если пользователь не выбирал закреплённое.
  Удалено автоматическое переключение. Явный выбор через список
  закрепов по-прежнему устанавливает `pinnedFocus`.
  Добавлен Android-тест `PinnedFocusNavigationRegressionTest` на
  синтетических сообщениях с двумя закрепами.
- **Проверка на дату обновления:** быстрый host CI прошёл
  [успешно](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40395592241);
  Android compile/эмулятор для обеих правок
  [завершены успешно](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40395592279):
  **29/29 PASS** на API 30, 0 ошибок и 0 пропусков.
- Разработка продолжается только в QA-ветке, `main` не изменяется.
  Оригиналы медиа не изменяются, GitHub содержит только синтетические тесты.

## Итерация: перемотка кружков, результат Android 29/29 и QA для телефона

- [Эмулятор Android API 30](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40395592279)
  завершил **29/29 PASS, 0 ошибок**: в том числе реальный резолв
  `%23/%3F` в именах медиа и переход к сообщениям без смены
  закреплённого. Проверка выполнялась на синтетических файлах.
- **P1 — перемотка чужого кружка при одинаковом MP4:** проверка
  `RoundPlaybackTarget` уже учитывалась при обычном нажатии, но
  **три callback'а SeekBar** проверяли только `a.path.equals(playingPath)`.
  Поэтому ползунок другого сообщения с тем же медиа мог ставить на
  паузу/перематывать активный. Условия заменены на
  `RoundPlaybackTarget.isSameTarget(playingPath,a.path,inlineHolder,holder)`.
  Это исправление кода подтверждено просмотром обработчиков; Android
  регрессия на двух реальных плитках пока **не выполнена**.
- Для проверки человеком добавлен
  [PHONE_QA_CHECKLIST_RU.md](PHONE_QA_CHECKLIST_RU.md) — короткие шаги
  с номерами A01–V02. Сначала проверить на копии экспорта, не передавая
  личные сообщения и скриншоты в публичный GitHub.
- [Офлайн host QA после исправления SeekBar](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40396573360):
