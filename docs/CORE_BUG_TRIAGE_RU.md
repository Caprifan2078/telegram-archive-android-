# Базовый пользовательский сценарий — разбор баг-репорта 0.50

**Дата разбора:** 26.10.2026. **Ветка:** `qa/v052-duplicate-id-safety-20261026`.
Цель — сначала подтверждать наличие дефекта в текущей версии, потом вносить
минимальное исправление с тестами. Не считать совпадение с прежним
скриншотом доказательством существования бага в текущем приложении.

## Критерий стабильности для обычного пользователя

Можно импортировать HTML-экспорт без потери прежнего архива; читать,
искать, возвращаться к сообщению; открывать/ставить на паузу/перематывать
доступные кружки, голосовые, фото и GIF; при отсутствии оригинала
приложение ясно сообщает о проблеме без ложной индикации воспроизведения
или падения. Временный скачок FPS — не основание объявлять потерю данных.

## Проверки, которые запускались

- [Сборка компактной QA APK и JVM-тесты](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40383727102):
  **PASS** для коммита `a9aa47fb97768aee2303876af1057c8686eaa695`.
  Это подтверждает сборку, **не** воспроизведение на Android.
- [Повторная сборка после исправления повторяющихся MP4](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40384553488):
  **PASS** для коммита `daf5a87174d0f0f8bafac17aa1d9a4942d0efe9b`.
- [Android instrumentation API 30](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40386217446):
  **12 выполнено, 11 PASS, 1 FAIL**. Ошибка:
  `RoundPlayerActivityTest.roundVideoActivityOpensAndAllowsSeeking`, перемотка
  на 900 мс не достигла хотя бы 600 мс за 170 мс.
  Тестовый H.264/MP4 длится 3 секунды и имеет только **один ключевой кадр
  в начале**. Это совместимо с ошибкой поиска ближайшего sync-кадра,
  но не доказывает, что сам видеодекодер неисправен.
- Исправлены полноэкранные вызовы перемотки: API 26+ запрашивает
  `MediaPlayer.SEEK_CLOSEST`, при ошибке есть fallback `VideoView.seekTo`.
  Новый инструментальный тест проверяет точность на **паузе** с ожиданием до
  2,5 секунд, что не позволяет естественному воспроизведению дать ложный PASS.
  Результат повторного [Android-прогона](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40387742728)
  **пока не подтверждён**.
- [Android compile smoke после missing-media патча](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40386217472):
  PASS. В медиатеке клик на карточке голосового переключён с системного
  внешнего плеера на штатный встроенный плеер, с отдельной regression-проверкой.
- Реальное устройство пользователя, узкие экраны, большие пользовательские
  переписки и фоновые переключения пока не проверены.
