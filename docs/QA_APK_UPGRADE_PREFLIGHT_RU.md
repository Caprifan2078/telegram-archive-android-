# Предпроверка безопасного обновления Telegram Archive Viewer (11.11.2026)

**Назначение:** не допускать попытку незаметно заменить существующую Android-установку новой APK с другим package ID, сертификатом или неподходящим `versionCode`. Проверка только читает файлы и не вызывает `adb install` или `adb uninstall`.

## Подтверждённый базовый файл, но НЕ подпись устройства

В предоставленном ранее файле `TelegramArchiveViewer_latest.apk` (точная копия `TelegramArchive_2026-11-05_Latest_QA.apk`) содержится APK с:
- размером 3 617 276 байт и SHA-256 `af5093dabdc1b48f8ef950da2970038882fbbfa9e6f710a597703b1ca6af54d2`;
- APK Signature Scheme v2 и сертификатом `C=US,O=Android,CN=Android Debug`, SHA-256 `d6b1491fb5b4a57b643cb3e8142486ec9082f145cbd539273e6b8bed55f81d48`;
- встроенной метаинформацией исходного git-commit `9cbb121d93a8c4c39ee2fa11d82d98bb1e3d36e3`;
- старым `workQa` вариантом приложения (по Gradle: ID `org.openarchive.telegram.qa.workqa20261028`, `versionCode=51` без override).

ZIP `TelegramArchive_Latest_QA_2026-11-05.zip` содержит точно такой же `app-workQa.apk`; SHA-256 ZIP `c27ad14a0577e2e5396490eb86b3c4de3e7055fc8dae3e73449b5227777b237f`. CRC ZIP и APK проверены локально. SHA-сертификат извлечён из APK v2 signing block и декодирован как X.509; независимая полная проверка APK подписи `apksigner verify` в текущем локальном контейнере не выполнялась.

**Эти факты подтверждают байты предоставленного файла, но НЕ то, какая версия действительно установлена на телефоне.** Для безопасной проверки обновления необходимо сравнить *точный установленный APK* с кандидатом.

## Проверка перед установкой

Нужны Android SDK build-tools (`aapt` и `apksigner`) и две APK: текущая установленная версия и кандидат. Инструмент в репозитории:

```bash
python3 scripts/check_apk_upgrade.py ./installed.apk ./candidate.apk \
  --build-tools "$ANDROID_HOME/build-tools/35.0.0"
```

Утилита выполняет `apksigner verify --print-certs` для **обоих** файлов, читает package ID и `versionCode` через `aapt dump badging`. Результат **положительный** только при выполнении всех условий:
1. Обе APK имеют один package ID.
2. Обе подписаны одним и тем же единственным сертификатом SHA-256.
3. У кандидата `versionCode` строго больше, чем у старой APK.

При неверной подписи, ином ID, недоступном инструменте, неопознанном сертификате или понижении/равенстве кода — блокировка. Нестандартное обновление с Android signing lineage / ротацией ключа здесь **не подтверждается**: для него нужен отдельный platform-level тест; утилита намеренно консервативна.

После положительной предпроверки всё равно необходимы резервная копия, её повторное чтение и реальное безопасное обновление с сохранением чатов, избранного, заметок и вложений. Это **не гарантия**, что миграции баз данных и интерфейс работают.

## Как получить именно установленную APK

На своём компьютере с включённой отладкой USB и разрешённым устройством:

```bash
adb shell pm path org.openarchive.telegram.qa.workqa20261028
```

Команда выводит, например, строку `package:/data/app/.../base.apk`. Скопировать **точный** путь в `adb pull`, если устройство позволяет, и выполнить предпроверку извлечённого `base.apk`. При наличии нескольких split APK, иных package ID, отказе в доступе или невозможности подтвердить установленный сертификат **не пытаться обновить вслепую**.

## Что ещё не подтверждено

- Ключ, которым подписана реально установленная пользователем APK, нам недоступен.
- Новый build `workQa` обычно получает временный debug-сертификат CI и может не подойти для обновления поверх старого `workQa`.
- Постоянный `stableQa` имеет **другой package ID**: `org.openarchive.telegram.qa.previewstable`. Он должен устанавливаться отдельно; перенос данных туда возможен только через проверенное экспорт/восстановление.
- Тестовые ключи в GitHub Actions создаются *исключительно для синтетического сценария* и не подходят для установки реальным владельцам.

**Не удалять старое приложение с пользовательскими данными; не использовать `adb uninstall` ради обхода отказа Android.** `main` и выпуск Stable не изменять до получения реальных подтверждений.
