**Срез:** 28.10.2026. **Репозиторий:** `Caprifan2078/telegram-archive-android-`. **Ветка документа:** `qa/modular-audit-matrix-20261028`.
**Основная ветка `main` не изменяется.** Это существующий проект; не начинать заново, не удалять функции и не публиковать реальные переписки, видео, скриншоты, пароли, архивы и подписи APK.

## Цель и границы

Проверять **одну составляющую за раз**, а не объявлять «приложение исправно» после общего smoke-теста. Тест каждого модуля должен действительно нажимать его действия и проверять **результат**, включая сохранение после закрытия диалога, повторного открытия экрана, смены чата и пересоздания Activity. Сначала пустой экран, затем синтетические данные, затем ограничения (узкий экран/шрифт/поворот/мало памяти), затем проверка регрессий. Случаи с реальными устройствами отмечать отдельно.

Базовые подтверждённые факты: старая QA-сборка `qa/responsive-media-grid-20261028` прошла 55/55 Android core/media instrumentation на Android 11: [run 40742718988](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40742718988). **Это не проверка всех пунктов меню.** Новый модуль UI Automator на `qa/ui-menu-tour-20261028` подтвердил 2/4 теста, 2/4 ещё **не прошли**: сохранение первого варианта performance и переход «Назад» после выбора полной копии ([run 40750297978](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40750297978)). Исходные `B01–B26` из `docs/BUG_REPORT_RECHECK_20261026_RU.md` включить в соответствующие группы. Никаких ложных «100% исправлено».

## Единые статусы

- **НЕ НАЧАТ** — систематическая проверка этого модуля ещё не завершена, даже если старые отдельные тесты существуют.
- **В РАБОТЕ** — составлен сценарий и запущены или анализируются тесты.
- **НАЙДЕН БАГ** — есть воспроизведение и доказательство, включая точную последовательность действий.
- **FIX / CI** — исправление в отдельной QA-ветке; итог сборки и тестов известен отдельно.
- **EMULATOR PASS** — синтетические сценарии на названной версии Android прошли; не значит «на всех телефонах».
- **DEVICE PASS** — пользователь подтвердил на реальном телефоне с указанием версии/устройства.
- **БЛОКЕР** — без этого безопасность выпуска не подтверждена.

## Порядок работы: проверять по одному

**Фаза A — базовое использование:** QA-00 → QA-01 → QA-02 → QA-03 → QA-04.
**Фаза B — файлы и медиа:** QA-05 → QA-06 → QA-13.
**Фаза C — дополнительные возможности:** QA-07 → QA-08 → QA-09 → QA-10.
**Фаза D — ввод, настройки и обучение:** QA-11 → QA-12 → QA-14 → QA-15.
**Фаза E — выпуск:** QA-16 → QA-17.

Приоритетный **P0-риск QA-17** (подпись/обновление) и риск потери данных при QA-11/12 остаются открытыми даже при тестировании других модулей. Нельзя тестировать реальное восстановление на рабочей установке с ценными данными.

## Контрольный набор для КАЖДОГО модуля

1. **Инвентаризация:** актуальные подписи кнопок, все варианты/переключатели, точки входа (главное меню, контекстное меню, переходы из других вкладок), пути назад.
2. **Позитивные действия:** клик, долгое нажатие, повторный клик, отмена, повторное открытие; проверка именно *состояния*, а не наличия заголовка.
3. **Негативные действия:** пустая БД/нет файла/отказ разрешения/повреждённый файл/двойной клик/отсутствует второй чат.
4. **Сохранность:** повторный вход, смена чата, возврат, пересоздание Activity, фон/возврат; для настроек сравнить `SharedPreferences`, для данных — БД и оригиналы.
5. **Визуальная матрица:** 320dp, 360–400dp, планшет и split-screen; масштаб текста 100%, 130%, 150%; светлая и тёмная тема, вертикально и горизонтально, системная клавиатура.
6. **Ресурсы:** быстрое переключение, долгий скролл, тайминги/память, повторное открытие, низкая память на эмуляторе; никаких недоказанных FPS.
7. **Регрессия:** отдельный `@Test`, CI на GitHub, скриншот/лог исключительно с синтетическими данными, проверка прежних тестов после исправления.
8. **Итоговая карточка:** ожидаемо/фактически; шаги воспроизведения; версия APK/Android; severity P0/P1/P2/P3; commit; Android CI link; `EMULATOR PASS` отдельно от `DEVICE PASS`.

## Первый модуль: QA-00 «Каркас и навигация» — конкретный чек-лист

- [ ] Старт с **0 чатов**, видны «Мои переписки», список/пустое состояние, добавить чат и ☰.
- [ ] ☰ открывается и закрывается нажатием вне панели / Android Back, без зависания и перекрытия статус-бара.
- [ ] Каждый из четырёх раскрывающихся разделов открывается и закрывается повторным нажатием. Пролистывание меню вверх/вниз.
- [ ] Открыть из ☰ безопасные пункты и отменить их: импорт (без подтверждения), бэкап (без создания), проверка, dry-run, восстановление (без подтверждения), квитанция, поиск, студия, медиа PRO, производительность, настройки, шрифты, помощь, учебный режим.
- [ ] Пункты, требующие открытого чата, на главной показывают корректное предупреждение и не уводят на неинициализированную БД.
- [ ] Внутри синтетического чата: ≡, две нижние вкладки, верхняя стрелка назад, боковая кнопка «Все чаты».
- [ ] После смены таба заголовок, статус, фильтры, Back и скролл принадлежат выбранному экрану. Всплывающее окно закрывается без случайной активации соседнего пункта.
- [ ] Перейти в справку из чата и обратно, пройти категории → подразделы → главу; Back возвращает на исходный экран.
- [ ] Нажимать переключатели темы и настроек только на синтетическом профиле; состояние проверить **после** закрытия и повторного открытия.
- [ ] Тестировать 320dp и fontScale 1.3 / 1.5; нижние панели, строки меню и диалогов без обрезания.
- [ ] Отдельно задокументировать фактические провалы UI Automator от 28.10.2026 (performance prefs и backup «Назад»). Перепроверить руками на эмуляторе и по screenshot/Accessibility, отделить дефект кода от дефекта теста.
- [ ] Отчёт QA-00: перечень *нажатых* элементов; неиспытанные экраны; баги с reproduction; ссылка на CI/снимки; оценка готовности именно QA-00.

**Фикстуры:** A — пустая изолированная установка; B — синтетический один чат (~12 сообщений, фото/голосовые/видеокружок), C — два синтетических чата с совпадающими путями медиа/именами, D — 1000+ записей для прокрутки. **Никаких личных данных**.

## Соглашение для последующих итераций

Для каждой QA-группы создавать `docs/qa/modules/QA-XX_REPORT_RU.md` с находками и результатами. Исправлять только в отдельной QA-ветке, не переписывать проект, не менять `main` и не откатывать полезные функции из веток Work. После исправления выполнить узкие тесты конкретного модуля **и** прежний регрессионный набор. Не повышать статус без завершённого CI; не считать диагностические/инструментальные сбои доказательством багов Android. При обнаружении риска потери данных — остановить опасный сценарий и тестировать на копии.

**Следующий практический шаг:** QA-00, после него QA-01 (все чаты) и QA-02 (обычная переписка). Двигаться по одному и фиксировать DONE только с доказательствами.
