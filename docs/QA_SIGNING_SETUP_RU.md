# Постоянная подпись QA: подготовка, ограничения и проверка

Критический риск B21: существующие сборки preview51 подписаны разными ключами.
Сохранить установленное приложение и создать полную резервную копию до любых
операций. Новый вариант `stableQa` имеет отдельный ID
`org.openarchive.telegram.qa.previewstable`: он устанавливается рядом,
но не видит внутренние данные старого приложения. Данные переносятся только
через полную копию и проверенное восстановление.

## Подготовлено

`stableQa` требует закрытый keystore и четыре переменные окружения; при
отсутствии любой из них сборка завершается ошибкой. Workflow
`stable-qa-signing.yml` запускается вручную, получает ключ из GitHub Secrets,
проверяет подпись и сравнивает SHA-256 сертификата с заранее заданной GitHub
Variable. Архив с APK выгружается только после успешной проверки. Секреты и
keystore не включать в Git и не отправлять в чат.

## Что должен сделать владелец

1. На доверенном компьютере создать отдельный закрытый QA keystore командой
   `keytool -genkeypair -v -keystore telegram-archive-qa.jks -alias archive-qa -keyalg RSA -keysize 3072 -validity 10000`.
   Задать надёжные пароли, сохранить резервную копию ключа и паролей в
   защищённом месте. Потеря ключа сделает будущие обновления невозможными.
2. Получить SHA-256 сертификата через `keytool -list -v -keystore telegram-archive-qa.jks -alias archive-qa`.
   Сохранить отпечаток без двоеточий как GitHub Actions Variable
   `ARCHIVE_QA_CERT_SHA256` (ровно 64 шестнадцатеричных символа).
3. В настройках репозитория создать GitHub Actions Secrets:
   `ARCHIVE_QA_KEYSTORE_BASE64` (base64 всех байтов keystore без переносов),
   `ARCHIVE_QA_STORE_PASSWORD`, `ARCHIVE_QA_KEY_ALIAS`,
   `ARCHIVE_QA_KEY_PASSWORD`. Не публиковать эти значения.
4. Запустить вручную workflow **Stable QA signing verification** из рабочей
   QA-ветки и проверить его статус. Это ещё не релиз и не заменяет Android QA.
5. На синтетическом архиве проверить первый install, создание данных,
   последующую сборку с тем же ключом и install -r без удаления приложения;
   затем сверить сообщения, избранное, настройки и полную копию.

Нельзя обновить уже установленные preview51 новым сертификатом или другим ID.
Не удалять прежнюю установку ради обновления. Пока этап 5 не пройден и
основные функциональные и визуальные ошибки не закрыты, приложение не Stable.
Результаты проверок этого нового workflow и теста обновления отсутствуют.
