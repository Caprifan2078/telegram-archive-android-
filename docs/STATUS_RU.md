## Критически важный риск: подпись тестовых APK

Повторный аудит 26.10.2026 подтвердил, что сертификаты двух последовательных
сборок `org.openarchive.telegram.qa.preview51` **не совпадают**.
`signingConfigs.debug` на разных GitHub runners не является постоянным
ключом QA-релиза. Это создаёт **P0-риск безопасного обновления**:
`INSTALL_FAILED_UPDATE_INCOMPATIBLE` и потенциальную потерю QA-данных
при вынужденном удалении прежней установки. Не объявлять Stable.
Публичный репозиторий не должен содержать приватный signing keystore.
Нужна постоянная подпись через Secrets и проверка обновления без удаления БД.
Полная матрица [B01–B26 и P0](BUG_REPORT_RECHECK_20261026_RU.md).

## Исправления текущей рабочей ветки

**Duplicate Telegram ID / reply-to**: исторически конфликт двух и более
оригинальных Telegram-ID молча сопоставлял ответ первому сообщению. Теперь
временная таблица отмечает такой ID отрицательным `message_id` и исключает
его из публикуемой карты. Все сообщения остаются в индексе, неоднозначный
ответ помечается как неразрешённый, другие ссылки сохраняются.
Схема SQLite не меняется. После исправления конфликта ID в эту же
ветку добавлен потоковый импорт HTML через jsoup `StreamParser`: HTML
читается последовательно, обработанные элементы удаляются из дерева.
Ограничение сегмента 8 МиБ; корректность и пиковая память на Android
пока не подтверждены. Добавлены Android-инструментальный и Python/SQLite host
регрессионные тесты на 3 одинаковых ID. Также добавлен синтетический Android
тест отказа второй HTML-части: старая опубликованная база и избранное
должны сохраниться без частично опубликованного импорта.

## Итерация: поиск, читаемость аналитики и автоматические тесты

- Исправлено индексное расширенное FTS4-поиск для русского `е/ё`.
  FTS4 `unicode61` различает эти буквы: раньше планировщик молча
  заменял `ё` на `е` и терял настоящие совпадения.
  Теперь точный вариант сохраняется, а при расширенном поиске
  добавляются ограниченные орфографические альтернативы.
  Отключённое расширение продолжает искать только исходное написание.

  и ограниченно проверяет стартовые префиксы как с `е`, так и с `ё`.
  Изменены `FuzzyWordPolicy`, `IndexedTypoLookup` и

## Реально проверено

- **В текущем сеансе:** архив целиком проходит ZIP CRC; синтетический
  SQLite-сценарий «три повторяющихся ID / уникальная ссылка / отсутствующая цель»
  прошёл на хосте. Это НЕ Android-интеграционный тест.
- **В материалах предыдущих сеансов:** 0.50 QA собрана в CI,
  189 JVM-тестов PASS, 1 миллион синтетических сообщений в host SQLite.
  Эти показатели относятся к прошлой версии и **не подтверждают 0.51**.
- **Android instrumentation:** для 0.50 было 0 выполненных тестов
  (сбой запуска эмулятора); новые Android-тесты и полная сборка 0.51/0.52
  в данном сеансе не запускались. APK текущей ветки **нет**.
- **Безопасность CI:** workflows ограничены условием запуска только
  на public-репозитории; приватность репозитория не менялась,
  платные runner-минуты в приватном режиме не тратились.

## Как продолжать

Работать с `qa/v052-duplicate-id-safety-20261026`, не создавать новый проект.
Сначала выполнить `python3 qa/host_tests/test_yo_search_sqlite.py`,
`python3 qa/host_tests/test_telegram_id_collision_sqlite.py`,
`python3 qa/host_tests/test_media_fixture_independence.py`
и `bash qa/host_tests/test_tgs_payload.sh`,
затем `gradle testCompactQaUnitTest assembleCompactQa` (с Android SDK),
после чего instrumentation на подходящем Android-эмуляторе/телефоне.
Перед переносом `main` сравнить обе ветки и их CI-конфигурации.
Никогда не загружать пользовательские переписки/видео/фотографии в GitHub
или Actions; тестировать только на синтетических данных.

## Подсветка Unicode в поиске (27.10.2026)

- Подтверждена ошибка: преобразование исходного сообщения в нижний регистр может менять длину строки. Например, `İx` превращается в `i̇x`; прежняя позиция совпадения `x` указывала за пределы исходного текста Android и могла приводить к ошибке при установке подсветки.
- Добавлена `SearchHighlightPolicy`: диапазоны вычисляются регулярным выражением по исходной UTF-16 строке, запрос экранируется как буквальный текст. Лимит 30 совпадений на слово сохранён. Алгоритмы FTS и состав результатов поиска не менялись.
- Локальный JVM-прогон проверил изменение длины регистра, эмодзи, кириллицу и буквальные символы регулярных выражений. Добавлены модульные тесты и проверка реальных Android `SpannableString` spans.
- [Android 11: 33/33 теста PASS](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40413702797), включая Unicode и возврат к результатам. [JVM и сборка PASS](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40413702784); [host PASS](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/40413702810).
- Полная переработка поиска и анализа, проверка на физическом телефоне и постоянная подпись остаются открытыми. APK не объявляется готовой к выдаче.

- В семи местах аналитики размеры дважды переводились из dp в пиксели. На экранах с высокой плотностью это увеличивало строки тепловой карты, календаря и графиков. Перевод теперь выполняется один раз.
