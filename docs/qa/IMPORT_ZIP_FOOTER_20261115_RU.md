# QA 15.11.2026 — неполный Telegram ZIP ошибочно проходил импорт

**Статус:** исправлено в QA-ветке `qa/import-zip-footer-20261115`, версия остаётся **0.51 QA**. Основная ветка `main` не изменялась. Новая APK с этим исправлением **не выпущена**.

## Дефект

`ArchiveFileImport.extractZip` и `extractZipWithPassword` распаковывали локальные ZIP-записи через `ZipInputStream`, не требуя конца центрального каталога (EOCD). Даже после удаления 22 завершающих байтов ZIP Java `ZipInputStream` способен прочитать все локальные файлы и завершить итерацию без IOException. Приложение могло принять повреждённый/неполный экспорт Telegram за полноценный архив.

**Реальное RED:** [CI 43651578262](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/43651578262) — Android 11, **2 ожидаемых FAIL из 4**: обрезанный EOCD без комментария и с комментарием были приняты старым кодом. Обычный корректный ZIP и ZIP с комментариями прошли. Компиляция/JVM были успешны. Независимый локальный Java-пробник воспроизвёл принятие ZIP после удаления последних 22 байт.

## Исправление

В `ArchiveFileImport.java` оба пути — обычный ZIP и ZIP с паролем (включая AES) — используют ограниченный по памяти `ZipEndGuard`. После обработки всех элементов проверяются EOCD/ZIP64, размер и смещение центрального каталога, совпадение количества локальных и каталогизированных элементов. При ошибке обычный `extract()` удаляет только временную распаковку. Пользовательский ZIP не изменяется. Границы: защита EOCD не является полной экспертизой всех метаданных центрального каталога; она обнаруживает характерные усечения и неконсистентность перечисленных полей.

Добавлен `ArchiveZipFooterImportRegressionTest`: обрезка стандартного ZIP с комментариями и без, полный ZIP с комментарием и без, AES ZIP с завершающей записью и без неё. В промежуточном [run 43651879557](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/43651879557) из 6 тестов один упал по **ошибке самого теста**: тест ожидал фотографию, отсутствовавшую в синтетическом AES-файле. Это было подтверждено XML (`ArchiveZipFooterImportRegressionTest.java:59`), исправлено проверкой, соответствующей составу фикстуры. В [run 43652333519](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/43652333519) из 47 тестов **46 PASS, 1 FAIL** по той же прежней ошибке теста; исправлен на последнем коде.

**Финальный GREEN:** [CI 43652574529](https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/43652574529) — **47 Android тестов, 0 failures, 0 errors, 0 skipped**, Android 11, JVM/build SUCCESS. Числа проверены по оригинальному XML-артефакту, а не только по строке лога. Соседние классы: ArchiveEndToEndRegressionTest, MultipleChatArchiveRegressionTest, EncryptedTelegramImportRegressionTest, SevenZTelegramImportRegressionTest, RarCompatibilityRegressionTest, ImportRollbackRegressionTest, ZipFooterIntegrityRegressionTest, ArchivePreviewIntegrationTest.

- Ветка с исправлением **не входит в предыдущую скачанную QA APK от 15.11**: она собрана ранее с коммита `60dc82ee`. Для установки новых исправлений потребуется отдельно выпустить и проверить новую изолированную QA APK.
- Оригинальная установленная APK, её подпись и сохранность обновления на реальном устройстве остаются P0. Старую установку не удалять.
