## 4. Функции — уровень доказательства

- Исходный код имеется для офлайн-просмотра экспортов Telegram, сообщений и поиска, ответов/цитат, избранного/заметок, аналитики, медиа, экспорта PDF, резервных копий, настроек и помощи. Наличие кода ≠ всесторонняя работоспособность.
- Импорт HTML и архивов ZIP/7z/RAR, включая отдельные сценарии зашифрованных архивов и rollback, покрыт синтетическими тестами. Текущая реализация **отклоняет архив с несколькими корневыми папками разных переписок** вместо молчаливого импорта только одной; импорт одной переписки с несколькими `messagesN.html` разрешён. Наиболее свежий фикс от 05.11 убрал ограничение глубины обнаружения вторых корней; targeted CI PASS.
- Перемотка OGG/Opus через UI синтетически проверена на Android 8, 11 и 15; другие кодеки/производители не проверены.
- В старых отчётах подтверждены базовая установка workQa на **чистом эмуляторе** и старые UI-сценарии, но не установка этого последнего APK на физическом устройстве.

## 5. Открытые риски и приоритеты

1. **P0:** совпадение подписи с реальной установленной версией, безопасное обновление без утраты БД/заметок/медиа. Прежние debug-сертификаты отличаются. Стабильный QA build тип уже предусмотрен (`stableQa` и внешние переменные keystore), **оригинального ключа в репозитории нет**. Ничего не удалять и не пытаться обновлять несовместимой подписью.
2. **P0:** проверить сохранность на реальных (обезличенных/локальных) больших архивах, прерывание импорта, process-kill/недостаток места, повторный импорт и восстановление бэкапов. Синтетические результаты не покрывают все эти сценарии.
3. **P1:** физический Android 8–15+, особые OEM-кодеки, кружки TGS/WebM/OGG/MP4, фон/пауза/TextureView; доступность SeekBar, TalkBack и 130–150% шрифт; длительная прокрутка/поиск/аналитика.
4. **P1:** проверить UX для полного экспорта Telegram с несколькими чатами. Текущая безопасная стратегия — отказ с ясной ошибкой; полноценный многодиалоговый импорт одной операцией **не реализован/не подтверждён**.
5. **P2:** систематическое прохождение QA-00—QA-17 (18 модулей), вместо признания их готовыми по узким регрессиям. Внутренние документы иногда говорят «QA-00—QA-18» как о 19 этапах; матрица содержит 18 модулей с номерами 00…17. Уточнить 18-й как выпускной этап, не подменяя факты.
6. **P2:** PDF ограничен старой реализацией: максимум 250 страниц, вложенные медиа в PDF не внедряются; проверить соответствие текущему требованию.
7. **P3:** Windows/Linux/macOS/iOS/HTML — отдельные платформы без проверенного выпуска в этом Android-репозитории.

## 8. QA 09.11.2026 — источники медиа для полной резервной копии

**Отдельная QA-ветка:** `qa/backup-unreadable-source-20261109`, основание `qa/recovery-audit-20261109` (`22e4a5de`). Main не изменять.

**P0 (выявлено анализом кода):** `DocumentFolder.children` в варианте локальной папки возвращал пустой список при `File.listFiles()==null`; SAF-ветка — при `ContentResolver.query()==null`. Метод `FullBackup.traverse` воспринимал это как ноль файлов, и экспорт мог завершиться с `full-manifest.json` несмотря на недоступную папку; отсутствие файлов не отличалось от ошибки чтения. Риск: полная копия без части медиа, при том что пользователь считал её полной.

**Код фикса:** `app/src/main/java/org/openarchive/telegram/DocumentFolder.java`, commit `8c8370083420b826220a07910e7b237836ea0993`. При `null` список не заменяется `[]`: явный `IllegalStateException` с безопасным локализованным текстом; настоящий пустой список по-прежнему считается допустимым. Не меняет формат сохранённых резервных копий, DB или пользовательские пути.

**Новые регрессии:** `app/src/androidTest/java/org/openarchive/telegram/FullBackupSourceAccessRegressionTest.java`, последние тестовые изменения `2b6948c58c08e55620c6f7d1c8e28644fbe0429f`. Проверки: (1) несуществующая локальная папка должна прерывать полный экспорт и не трогать предыдущую БД/избранное; (2) путь, указывающий на обычный файл; (3) отсутствующий SAF provider; (4) существующая пустая папка успешно экспортируется с нулём медиа.

**CI:** `.github/workflows/backup-source-access-20261109.yml`; до исправления `https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/42537920307`; после исправления + SAF проверки `https://github.com/Caprifan2078/telegram-archive-android-/actions/runs/42538012659`. Статусы на момент первого написания документа **выполняется/ожидает**, результат проверять отдельно: **не считать PASS до просмотра CI**.

**Следующий шаг:** проверить оба прогона, отличить ожидаемый RED теста от случайного сбоя сборки, убедиться в целевом GREEN; затем обновить проверенный SHA и провести регрессию близлежащих операций экспорта/импорта.
