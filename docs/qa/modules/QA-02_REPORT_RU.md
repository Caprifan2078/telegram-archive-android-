# QA-02 — Чтение переписки: защита позиции при смене архива

**Дата:** 02.11.2026. **Ветка:** `qa/qa02-reading-progress-fixed-20261102`. **База:** `qa/work-modular-audit-00-18` (commit `ac53ee3640de14a4aacced950e5ff146da80614d`). `main` не изменяется.

## Инвентаризация первого сценария
- `MainActivity.saveReadingProgress()` сохраняет `read_id_<archive>`, `read_top_<archive>`, `read_offset_<archive>` из действительно видимых сообщений.
- `activateArchive(key)` переключает SQLite и запускает восстановление сохранённой позиции асинхронно.
- `renderMessages()` строит сообщения и восстанавливает scroll anchor.
- Сначала проверить работу на двух синтетических чатах, затем на пустых/временных контейнерах без карточек.
- Другие сценарии QA-02 (медиа, 100k сообщений, поворот, прокрутка, reply) остаются для отдельной итерации.

## Выявленная ошибка по коду

**QA02-001, P2, позиция чтения другого чата.** До изменения `activateArchive` не обнулял `lastVisibleMessage/lastVisibleTop` после переключения архива. Если `saveReadingProgress()` не находил ни одной карточки с tag типа Long, он мог взять старый ID поля и сохранить его как `read_id` уже для нового архива. Это особенно рискованно при временных экранах загрузки и быстрых переключениях.

**QA02-002, P2, устаревшее фоновое восстановление.** Асинхронная задача `activateArchive` использовала mutable `db.positionFor()` вместо снимка конкретной БД, при быстром переключении чата могла прочитать другой архив или закрытую БД. Исправление учитывает идентичность БД до фонового запроса и перед применением результата.

## Исправление в отдельной ветке

- При переключении чатов сбрасываются только *временные поля текущего Activity*, **не хранимые в SharedPreferences позиции**.
- Сохранение позиции допускается только при наличии реального `Long`-ID на карточке; placeholder не может переписать сохранённые данные.
- Если прокрутка ниже последней карточки, выбирается последний реально отрисованный ID как безопасный fallback.
- Асинхронная задача восстановления привязана к изначальному экземпляру `MessageDb`; устаревшие результаты не применяются. Отказ обращения к закрытой БД обрабатывается безопасно.
